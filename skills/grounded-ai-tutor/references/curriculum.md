# Curriculum map

Use this as a routing map, not a fixed syllabus.

```text
How a computing system works
  ├─ Hardware and operating system
  ├─ Network and Web
  ├─ Frontend and browser
  ├─ Backend and APIs
  ├─ Data and persistence
  ├─ AI models and applications
  ├─ Engineering and operations
  └─ Career evidence and communication
```

## Hardware and operating system

CPU, memory, storage, files, programs, processes, threads, command line, users, permissions, Linux, containers. Goal: explain why and how a program runs.

## Network and Web

IP, routers, DNS, ports, TCP and UDP, HTTP and HTTPS, proxies, browsers, servers, deployment and security. Goal: trace a request across machines and layers.

## Frontend

HTML, CSS, JavaScript, TypeScript, rendering, components, state, routing, forms, API calls, Vue and React. Goal: trace how a visible page appears and changes.

## Backend

APIs, routes, authentication, authorization, business logic, services, concurrency, queues, caches, scheduled work, errors and logs. Goal: trace one user action through server-side behavior.

## Data

Databases, tables, rows, columns, keys, queries, indexes, transactions, migrations, backups and Redis. Goal: explain where durable facts and temporary state live.

## AI

Training, inference, models, parameters, tokens, context, prompts, tools, vectors, RAG, agents, evaluation, cost, privacy and safety. Goal: separate model behavior from product behavior and design reliable applications.

## Engineering and operations

Git, branches, tests, environment variables, containers, CI/CD, releases, monitoring, alerts, logs, backups and incident review. Goal: explain how changes reach users safely.

## Career evidence

Start from the learner's desired outcome. Distinguish real delivered work, reproducible public projects and learning experiments. Do not turn unknown background details into career ceilings.
